# QUIC Requirement Gaps

This ledger tracks open questions, ambiguities, and follow-up decisions for QUIC requirement work.

## Open Gaps

- `interop-chacha20-runner-platform-policy` is closed for the current runner cell. `REQ-QUIC-INT-0018` now has local proof that the helper inventory classifies `chacha20` as supported/executed, and the real local `quic-go`/`quic-go` runner report under `artifacts/interop-runner/20260513-011027614-both-quic-go/runner-report.json` records `result: succeeded` for testcase `chacha20`. `InteropHarnessRunner` now exposes runnable `chacha20` client/server dispatch branches and that source seam is now paired with preserved live runner proof, so helper inventory plumbing, preflight cipher selection, or peer-slot breadth no longer needs to stay blocked on this lane.

- `interop-resumption-runner-keylog-proof` is closed for the current runner cell. The harness now emits opt-in NSS-style SSLKEYLOGFILE traffic-secret lines from the managed TLS schedule, preserving honest unsupported behavior for testcases that do not execute. A live `resumption` runner attempt on 2026-05-09 passed with runner report `artifacts/interop-runner/20260509-001723585-both-quic-go/runner-report.json` recording `result: succeeded`, so the explicit inventory can classify `resumption` as supported/executed. This does not claim HTTP/3, 0-RTT, anti-replay, external ticket persistence, public API widening, or broader resumption support beyond the checked runner cell.

- `interop-zerortt-runner-proof` is closed for the current runner cell. `REQ-QUIC-CRT-0153` owns the internal managed-server path for `early_data` ticket advertisement, validated same-listener early-data acceptance through `REQ-QUIC-CRT-0152`, server ZeroRtt packet opening, and bounded STREAM/PING/PADDING delivery proof. The harness now has a server-role `zerortt` dispatch path that enables managed resumption tickets plus server early-data admission and keeps the second connection open-ended for runner-driven request streams. The resumed second connection now uses a zerortt-specific request-gap timeout so the hosted proof can complete within the runner idle budget, and the request-line reader is now buffered instead of byte-by-byte so the proof path does not amplify receive-credit chatter. Hosted run `25777328991` on 2026-05-13 completed the advisory Linux `zerortt-server-proof` profile end to end and preserved packet-analysis evidence that 0-RTT request-stream data was sent and acted on. The successful bundle records `0-RTT size: 10570` and `1-RTT size: 2379`, and the helper inventory can now classify `zerortt` as supported/executed. Partial hosted proof, server-only dispatch, or internal runtime proof alone still must not be treated as support evidence.

- `interop-connectionmigration-socket-rebind-seam` is narrowed to live runner proof. The runtime path-state ledger already models internal migration promotion, path validation, and rebind-aware packet classification, and the endpoint host shell now retargets or recreates its connected UDP socket when a promoted path changes.
