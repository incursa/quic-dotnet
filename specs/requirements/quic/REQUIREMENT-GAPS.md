# Requirements Gaps

This ledger tracks open questions, ambiguities, and follow-up decisions for QUIC requirements. Keep entries short, traceable, and explicit about whether they are blocked on missing policy, missing design, or missing proof.

- `connect-udp` is a planning gap for `rfc9298.txt` sections `3`-`5`. Pressure class: `datagram adapter`, `HTTP/3 adapter`, and `stream adapter`. Current action is architecture planning only unless support is explicitly committed later. Allocation-sensitive seams: UDP payload ownership and HTTP Datagrams bridging, especially the same outbound datagram path used by `QuicConnectionRuntime` and `QuicListenerHost`.

- `connect-ip-masque` is a planning gap for `rfc9484.txt` sections `4.1`, `4.7`, `6`, `7`, `10`, `12.1`-`12.4`. Pressure class: `datagram adapter`, `HTTP/3 adapter`, and `diagnostics/manageability`. Current action is architecture planning only unless support is explicitly committed later. Allocation-sensitive seams: outbound datagram ownership, packet handling, and MTU-sensitive proxy flow, especially `QuicConnectionRuntimeEventModels.QuicConnectionSendDatagramEffect` and the adapter boundary above `QuicConnectionRuntime`.

- `dns-over-quic` is narrowed by `SPEC-QUIC-RFC9250`, `ARC-QUIC-RFC9250-0001`, `WI-QUIC-RFC9250-0001`, and `VER-QUIC-RFC9250-0001` for the initial DoQ foundation: ALPN `doq`, default UDP port 853 helpers, UDP port 53 rejection, DoQ error-code constants, and the RFC 9250 two-octet DNS-message length prefix. It is further narrowed by `ARC-QUIC-RFC9250-0002`, `WI-QUIC-RFC9250-0002`, and `VER-QUIC-RFC9250-0002` for the minimal query/response stream lifecycle: one client-initiated bidirectional stream per query, client FIN after query bytes, server response on the same stream, server FIN after response bytes, and concurrent queries on one connection. `ARC-QUIC-RFC9250-0003`, `WI-QUIC-RFC9250-0003`, and `VER-QUIC-RFC9250-0003` now narrow the first cancellation/resource-limit slice: client cancellation maps to `DOQ_REQUEST_CANCELLED` STOP_SENDING behavior, early client resets before FIN do not dispatch incomplete DNS transactions, internal handler failures map to `DOQ_INTERNAL_ERROR`, opt-in dangling-stream pressure closes the connection with `DOQ_EXCESSIVE_LOAD`, and configured cancellation-request volume limits close the connection with `DOQ_EXCESSIVE_LOAD`. `ARC-QUIC-RFC9250-0004`, `WI-QUIC-RFC9250-0004`, and `VER-QUIC-RFC9250-0004` narrow the first protocol-error slice: non-zero received DNS Message IDs, incomplete length-prefixed DoQ messages at STREAM FIN, and multiple client queries on one stream fail with `DOQ_PROTOCOL_ERROR` on the one-query path. `ARC-QUIC-RFC9250-0005`, `WI-QUIC-RFC9250-0005`, and `VER-QUIC-RFC9250-0005` now narrow the next fatal-protocol-error subset: early response FIN, extra response bytes, inbound unidirectional stream rejection, and the shared `CONNECTION_CLOSE`/`DOQ_PROTOCOL_ERROR` close behavior. `ARC-QUIC-RFC9250-0006`, `WI-QUIC-RFC9250-0006`, and `VER-QUIC-RFC9250-0006` now narrow the SERVFAIL response slice: handler-provided DNS responses whose response code is SERVFAIL are preserved and delivered to the client on the same stream without transport remapping. `ARC-QUIC-RFC9250-0007`, `WI-QUIC-RFC9250-0007`, and `VER-QUIC-RFC9250-0007` now narrow the peer STOP_SENDING slice: a client that receives STOP_SENDING on an outstanding query stream treats it as a fatal protocol error and closes the connection. Remaining RFC 9250 sections covering missing expected STREAM FIN timeout policy, edns-tcp-keepalive, server-initiated bidirectional stream fatal handling, unsolicited RESET_STREAM limits, padding policy, long-lived connection management beyond the basic reuse proof, AXFR/IXFR, flow-control profiles, Retry-address-validation posture, 0-RTT, DNS message-ID gateway rewriting, and external interop proof stay open until their own requirement-backed slices are implemented. Pressure class: `DNS/discovery edge`, `stream adapter`, and `transport-core`. Allocation-sensitive seams: stream delivery and handshake/resumption state, especially `QuicConnectionStreamSnapshot` and the `QuicConnectionRuntime` TLS/transport bridge flow.

- `encrypted-dns-discovery-and-provisioning` is a planning gap for `rfc9461.txt` sections `3.1`, `4.1`-`4.3`, `rfc9463.txt` sections `3.1`-`3.4`, `4.1`-`4.2`, `5.1`-`5.2`, and `6.1`-`6.2`, and `rfc9464.txt` sections `3.1`-`3.2`, `4.1`-`4.2`, and `5`. Pressure class: `DNS/discovery edge`. Current action is architecture planning only unless support is explicitly committed later. Allocation-sensitive seams: no QUIC hot-path seam; keep resolver/configuration data as scalar snapshots that enter the core only at bootstrap or endpoint selection time.

- `manageability-guidance-rfc9312` is now narrowed by `SPEC-QUIC-RFC9312`, `ARC-QUIC-RFC9312-0001`, `WI-QUIC-RFC9312-0001`, and `VER-QUIC-RFC9312-0001` for metadata-only diagnostics and qlog mapping across packet header observation, coalesced datagrams, connection ID lifecycle, migration/path validation, spin-bit state, ICMP Packet Too Big, PMTU updates, close/draining state, UDP errors, and anti-amplification blocking. Remaining RFC 9312 guidance that requires deployment policy, packet capture infrastructure, loss-bit support, DSCP/QoS, QUIC-LB, ECMP, or managed-network controls stays classified as documentation, not applicable, or future extension rather than runtime feature work. Pressure class: `diagnostics/manageability` and `interop/test-only`. Allocation-sensitive seams: diagnostics emission and packet/version observation, especially `QuicConnectionRuntime.DiagnosticsSink`, runtime event emission, and packet inspection helpers.
